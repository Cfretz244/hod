# WP-213 — x86-64 TLS descriptors (`-enable-tlsdesc`)

Landed: the option `-enable-tlsdesc` (`crates/hod/src/args.rs`,
`hod::Options::tls_descriptors`, `crates/hod/src/back.rs`, the help text
of `crates/hod_cli/src/driver.rs`; the shim passes `llc`'s arguments
through unchanged, so it needs nothing), `hod_cg::Options::tls_descriptors`,
`hod_cg::SymRef::TlsModuleBase` (an undefined global `STT_TLS`
`_TLS_MODULE_BASE_`, made by module emission on first use), the
encoder's `tlsdesc_call` (`FF 10`, `crates/hod_mc_x64/src/tls.rs`), the
lowering in `crates/hod_x64/src/tls.rs` (`descriptor_call`,
`descriptor`), `spec/codegen.md` §5.6.37, `spec/cli.md` "Options",
`spec/harness.md` (`-enable-tlsdesc` on the `llc-args` allow-list,
`xtask/src/irdiff/directives.rs`). Tests: `crates/hod_x64/tests/tls.rs`
(`descriptors_link_run_and_relax`, `descriptors_through_dlopen`, data
`tests/data/tls/dl.ll`, `peer.ll`, `dl_driver.c`),
`crates/hod_mc_x64/tests/l1/link.rs` (models `desc` and `ldesc`),
`crates/hod_mc_x64/tests/l1/tls.rs`, `crates/hod/src/args.rs` (unit
tests), `tests/ir/tls_desc.ll`.

## Before

`hod -enable-tlsdesc` was `unknown option '-enable-tlsdesc'` (exit 1;
exit 2 in strict mode); with a fallback the whole invocation went to
`llc`. Nothing was silently ignored. kiln 21caaf874 (the workspace's)
has no `-mtls-dialect` and passes no `-enable-tlsdesc`; nothing in it
was exercised here.

## Where the dialect is

Nowhere in the IR: `clang` 19 and 22 `-mtls-dialect=gnu2 -S -emit-llvm`
write the same module as without it (a C file with a defined and an
extern `__thread`, diffed); the driver passes `-enable-tlsdesc` to `cc1`
(`clang -###`), which is `llc`'s option. `clang-22` refuses
`-mtls-dialect=` for an AArch64 target. `llc` 19 and 22 accept
`-enable-tlsdesc` on AArch64 and change nothing: the objects of a module
with every shape below are identical without it, with it, `=false` and
`=0`. hod does the same (the AArch64 back end does not read the field).

## Census

Every shape: a preemptible definition, an `external`, an `extern_weak`,
a `hidden`, an `internal` (two in one function), a `dso_local`
definition, a thread-local operand returned as a value, a general-dynamic
access with three arguments live across it; and clang++ 19 and 22 IR of
C++ `thread_local` (dynamic initialization, so `_ZTW` wrappers and
`_ZTH`, `__tls_guard`, an `inline` variable with its guard `_ZGV3inl`, a
`static` one, a `weak` one, a class type with a destructor). Under
static (no PIC level), PIE and shared-object modules, both dialects, the
TLS relocations of `llc-19`, `llc-22` and hod, by type and symbol:

| module | dialect | relocations (`llc` 19 = `llc` 22 = hod in every row) |
|---|---|---|
| static, PIE | either | `GOTTPOFF` for `gd`(3), `ext`, `wk`; `TPOFF32` for `hid`, `ld`, `ld2`, `dl`: the option changes nothing |
| shared | gnu | `TLSGD` + `PLT32 __tls_get_addr` for `gd`(3), `ext`, `wk`; `TLSLD` + `PLT32` + `DTPOFF32` for `hid`, `ld`, `ld2`, `.Ldl$local` |
| shared | desc | `GOTPC32_TLSDESC` + `TLSDESC_CALL` for `gd`(3), `ext`, `wk`, and for `_TLS_MODULE_BASE_`(4) with `DTPOFF32` for `hid`, `ld`, `ld2`, `.Ldl$local` |
| C++, shared, clang 19 and 22 IR | desc | `GOTPC32_TLSDESC`/`TLSDESC_CALL` × `_TLS_MODULE_BASE_` 4, `_ZGV3inl` 2, `dyn` 2, `ext_dyn` 1, `inl` 2, `s` 3, `wk` 1; `DTPOFF32` × `_ZL2st` 2, `__tls_guard` 2 |

`_TLS_MODULE_BASE_` is an undefined `GLOBAL DEFAULT` symbol of type
`TLS` in `llc`'s object and in hod's.

`llc`'s code at `-O0` (19 and 22 the same, the bytes compared):

```text
general dynamic                       local dynamic
movq %fs:0, %rcx                      movq %fs:0, %rcx
leaq x@tlsdesc(%rip), %rax  48 8d 05  leaq _TLS_MODULE_BASE_@tlsdesc(%rip), %rax
callq *x@tlscall(%rax)      ff 10     callq *_TLS_MODULE_BASE_@tlscall(%rax)
addq %rcx, %rax                       leaq x@DTPOFF(%rax,%rcx), %rax
```

`R_X86_64_GOTPC32_TLSDESC` at the `lea`'s field (addend -4);
`R_X86_64_TLSDESC_CALL` at the call's first byte (addend 0). Clobbers:
the function with three `i64` arguments live across the access keeps
them in `rdi`, `rsi`, `rdx` across the call under `-enable-tlsdesc`
(`llc` spills them around `__tls_get_addr` without it): `llc`'s
`TLS_desc` defines `rax` and `eflags` only. The psABI's TLS descriptor
convention (Oliva and others, *Thread-Local Storage Descriptors for IA32
and AMD64/EM64T*) is the same: every register but `rax` preserved. The
large code model: `llc` 22 writes the same small-model pair under
`-code-model=large -enable-tlsdesc`; hod refuses `x64:code-model` with
or without the option (WP-209's).

hod writes the pair with `rax` exactly as `llc` and adds the thread
pointer after it (`add rax, fs:[0]`), so that the operand form needs no
second register; local dynamic adds `lea rax, [rax + x@dtpoff]`.
Around it: `pushfq`, `push rax` (or `lea rsp, [rsp - 8]` when the
result is `rax`), and after it `mov rd, rax`, `pop rax`, `popfq`
(§5.6.37). `llvm.threadlocal.address` of a dynamic model is that operand
too: nothing is displaced.

## Evidence

- **Bytes and relocations against LLVM's assembler, then the linkers**
  (`crates/hod_mc_x64/tests/l1/link.rs`): the descriptor pair plus `add
  rax, fs:[0]` (`desc`) and the `_TLS_MODULE_BASE_` form with a
  `DTPOFF32` `lea` (`ldesc`) assembled from hod's bytes and `.reloc`s
  equal `llvm-mc`'s text (`lea rax, [rip + x@TLSDESC]`; `call qword ptr
  [rax + x@TLSCALL]`) under LLVM 19 and 22, code and relocations; both
  objects linked by bfd 2.44, lld 22 and mold 2.37.1 into a static
  executable, a PIE and a shared object give identical files; in the
  executables the `lea` is rewritten, in the shared object it is kept and
  `R_X86_64_TLSDESC` is emitted.
- **Programs** (`descriptors_link_run_and_relax`): `tests/data/tls`'s
  library and main modules and C driver, six ways of linking (non-PIE,
  PIE, the library as a shared object, the library's dynamic models into
  a PIE, static, static PIE), three linkers, five threads, run under
  `qemu-x86_64` against glibc 2.41: hod (plain and under stress, §12),
  `llc` 19 and 22 with `-enable-tlsdesc`, hod's descriptors with `llc`
  22's `__tls_get_addr` objects and the reverse, hod's `__tls_get_addr`
  with `llc`'s descriptors: 117 programs, every one prints `checked`.
  What the linkers did to hod's 49 descriptor sequences of the library
  (read back from the linked code): shared object, 49 kept (every
  linker); into a PIE, bfd and lld 42 local exec and 7 initial exec, mold
  34 and 15; static and static PIE, bfd and lld 49 local exec, mold 41
  local exec and 8 initial exec (mold keeps another object's variables
  in a GOT entry the static link fills, as it does for AArch64's
  descriptors, §5.5). The same under stress. The relocations of the
  library object, by type and symbol, equal `llc` 22's in every build.
  The modules of an executable (no dynamic model) are byte-identical
  with and without the option.
- **`dlopen`** (`descriptors_through_dlopen`): `dl.ll` (descriptors,
  25 sequences) and `peer.ll` in one shared object loaded by `dlopen`,
  `peer.ll` built by hod without and with the option, by `llc` 22
  without and by `llc` 19 with it, so `dl_gd` has both a descriptor and
  a `__tls_get_addr` GOT entry; `dl.ll` also built by hod under stress
  and by `llc` 22; a TLS block of 16 bytes (the loader may place the
  module in the static block's surplus) and of 1 MiB (it cannot:
  per-thread dynamic allocation, the resolver's slow path); five
  threads, addresses against `dlsym`'s, values live in general and
  vector registers across the accesses, a `select` under a fused compare
  around one: 36 programs (2 sizes × 6 builds × bfd, lld, mold), all
  `checked`. Every linker keeps the 25 descriptors of `dl.ll`.
- **irdiff**: `tests/ir/tls_desc.ll` (`;@ llc-args: -enable-tlsdesc`):
  tls.ll's program with hidden and `dso_local` variables, its module
  without a PIE level so the dynamic models are written and the linker
  relaxes them in the program.
- **Byte identity without the option**: every 10th entry of the corpus
  (646 entries, 669 modules, both targets, LLVM 19 and 22), the base
  `84600c0c` and this head each built in its own target directory,
  `scripts/corpus-bytes.py -j 4`: 669 objects identical, 0 differ.

## Notes for others

- `llc` 22 writes the small-model descriptor pair under
  `-code-model=large` (WP-209).
- `llc` folds `%fs:0` into a register before the pair; any register
  but `rax` is kept across the call, which hod does not need.
