# WP-209 — the large code model

Landed: `-code-model=large` and the module flag `Code Model` 4 on x86-64
(PIC, PIE and static) and on AArch64 outside PIC, as `llc` 19 and 22
build them at `-O0` (`spec/codegen.md` §5.6.36). x86-64: the large
sections (`hod_cg` `emit/section.rs`, `is_large`), 64-bit addresses and
GOT sequences (`hod_x64` `common.rs` `far_access`, `far_address`,
`far_callee`, `far_branch`; the stack protector, coroutine and TLS paths
through them), the callee field `Reloc::branch` so a call of an
`available_externally` `alwaysinline` function still reaches its local
copy (`hod_cg` `emit/copy.rs`), `X86_64_LARGE` unwind tables and 8-byte
LSDA type entries (`hod_eh` `target.rs`, `lsda.rs`), the relocation kinds
`GOT64`, `GOTOFF64`, `GOTPC64` (`hod_obj` `reloc.rs`, `spec/object.md`,
`spec/mc-x64.md`). AArch64: `movz`/`movk` addresses
(`hod_a64` `common.rs` `large`, `far_address`, `movw_address`; `coro.rs`),
`AARCH64_LARGE` unwind tables. The matrix (`hod_ir`
`classify/matrix.rs`, `walk.rs`): `module:code-model-large` on for both
targets, the new `module:code-model-large-pic` refused on AArch64,
medium and kernel refused by name; `docs/status/support.md` (generated).
Tests: `crates/hod_x64/tests/large_code_model.rs` (and its
`tests/data/large`), `crates/hod_a64/tests/large_code_model.rs`,
`tests/ir/large_code_model.ll`, `tests/ir/large_code_model_static.ll`,
the refusals in `hod_x64/tests/mem.rs`, `hod_a64/tests/mem.rs` and
`coro.rs`.

## Census

What kiln writes for `-mcmodel=large` (LLVM 22 text, `--target=` each
target, with and without `-fPIC`/`-fPIE`/`-fno-pic`): the module flag
`Code Model` 4 always; on x86-64 also `Large Data Threshold` 0. Without
a PIC option kiln's default is PIE on both targets (`PIC Level` 2, `PIE
Level` 2). No variable carries a `code_model` attribute. So the variant
an x86-64 build hits is large PIE; on AArch64 it is large PIE too, which
clang refuses and kiln accepts (the difference is the kiln agents').

What `llc` 19 and 22 write (the two give the same sections and
relocations on every census module; `refs.ll`, a module with every kind
of reference, and `eh.cpp`'s IR for the tables):

| | x86-64 PIC | x86-64 static | AArch64 static | AArch64 PIC |
|---|---|---|---|---|
| text | `.ltext` `axl` | `.ltext` `axl` | `.text` | `.text` |
| data | `.ldata`, `.lbss`, `.lrodata*` `l` | same | small names | small names |
| TLS, `.data.rel.ro` | small | small | small | small |
| dso-local address | `GOTPC64` + `GOTOFF64` | `R_X86_64_64` | `MOVW_UABS_G0_NC`..`G3` | small PIC (`adrp`) |
| preemptible address | `GOTPC64` + `GOT64` | `R_X86_64_64` | GOT (`ADR_GOT_PAGE`) | small PIC |
| call | `movabs` + `call r11` | same | `bl` | `bl` |
| TLS | small sequences | small sequences | local exec only (else `llc` aborts) | local exec only |
| `.eh_frame` FDE | `pcrel|sdata8`, `PC64` | same | `pcrel|sdata8`, `PREL64` | `pcrel|sdata8` |
| personality / LSDA | 0x9c / 0x1c | absolute | 0x9c / 0x1c | 0x9c / 0x1c |

`refs.ll`'s relocations, `llc` 22 PIC: 14 `GOT64`, 9 `GOTOFF64`, 17
`GOTPC64`, 25 `PC64`, 3 `PLT32` (TLS calls), TLS 6; hod: 14, 5, 19, 20,
3, TLS 6 (hod computes the GOT's address at each reference; fewer
`GOTOFF64`/`PC64` where it folds an addend or has no constant pool).
Static: `llc` 29 `R_X86_64_64`, hod 20 (no jump tables or constant
pools). `llc` 19 is `llc` 22 to the relocation.

AArch64 large PIC is refused: `llc` keeps small-model code but writes
the 8-byte FDE, so it is not hod's small PIC output, and it aborts on
every TLS model but local exec ("ELF TLS only supported in small memory
model or in local exec TLS model"), which PIC code needs. Medium and
kernel are judged and refused by name (`module:code-model-medium`,
`module:code-model-kernel`): medium mixes 32-bit and 64-bit references
by a per-variable threshold, kernel is a different absolute model.

## Findings outside hod

- lld 22.1.8 writes `.eh_frame_hdr`'s table unsorted when an object's
  `.ltext` precedes the start files' `.text` (initial locations 0x3b30,
  0x18d0, 0x1950), so a throw terminates; `llc`'s objects fail the same.
  GNU ld and mold sort it; lld 19 sorts it with the start files but not
  when `--section-start` puts `.ltext` above a `.text` (the far layout
  gives `.text` just below `.ltext`). Kept as the ignored
  `lld_22_sorts_the_frame_index`; `tests/ir`'s large programs do not
  throw, and the large corpus sample runs under GNU ld and mold.
- mold 2.37.1 relaxes an AArch64 GOT load into `adrp` of the symbol and
  then reports the `adrp` out of range instead of keeping the GOT, and
  with `.data` placed far it moves `.got.plt` beyond the PLT's reach
  without an error (the program crashes). The far test passes
  `--no-relax` and places `.got.plt`.
- `llc` 19 does not parse kiln's `frame-pointer` value
  `non-leaf-no-reserve`.
- The far layouts depend on each linker's placement: `.eh_frame_hdr`'s
  table is 32-bit, so the code stays within 2 GiB of it; the start
  files' small-model code needs its data near, hence `-nostartfiles`
  and a small `_start`.
