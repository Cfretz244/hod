# WP-215 — the frame as an unwinder sees it

## Census

Taken before any lowering, with `llc` 19 and 22 at `-O0` (on AArch64
`-global-isel=0 -fast-isel=0`), clang 19 and 22, gcc and kiln, and the
corpus (`.build/corpus`, 6460 modules).

### Which builtin becomes which intrinsic

| builtin | clang 19 and 22 | kiln |
|---|---|---|
| `__builtin_frame_address(n)` | `llvm.frameaddress.p0(i32 n)` | the same |
| `__builtin_return_address(n)` | `llvm.returnaddress(i32 n)` | the same |
| `__builtin_extract_return_addr`, `__builtin_frob_return_addr` | the operand | the same |
| `__builtin_dwarf_cfa()` | `llvm.eh.dwarf.cfa(i32 0)` | undeclared identifier |
| `__builtin_unwind_init()` | `llvm.eh.unwind.init()` | undeclared identifier |
| `__builtin_eh_return(off, h)` | `llvm.eh.return.i64`, then `unreachable` | undeclared identifier |
| `__builtin_eh_return_data_regno(n)` | a constant (0, 1 on both) | undeclared identifier |
| `__builtin_dwarf_sp_column()` | a constant: 7 (x86-64), 31 (AArch64) | undeclared identifier |
| `__builtin_init_dwarf_reg_size_table(p)` | stores (x86-64); "cannot compile this builtin yet" (AArch64) | undeclared identifier |
| `__builtin_sponentry()` | `llvm.sponentry.p0()`, AArch64 only | undeclared identifier |
| `_AddressOfReturnAddress()` | not declared on Linux targets | — |
| VLA, `alloca` | `llvm.stacksave`/`stackrestore` | the same |

So kiln reaches only `frameaddress`, `returnaddress` and
`stacksave`/`stackrestore` today; the others come from `.ll` written by
hand or by clang.

### The corpus

No module calls `llvm.eh.dwarf.cfa`, `llvm.eh.return.*`,
`llvm.eh.unwind.init`, `llvm.sponentry`, `llvm.addressofreturnaddress`
or `llvm.localaddress`. `llvm.frameaddress` is in 8 modules (depth 0
only), `llvm.returnaddress` in 10 (depths 0 to 100, gcc's torture tests),
`llvm.stacksave` in 26.

### What hod did before this package

`frameaddress(n)` and `returnaddress(n)` up to depth 256 on both
targets (deeper: `x64:frame-depth`, `a64:frame-depth`), the AArch64
return address stripped with `xpaclri`; `stacksave`/`stackrestore`. The
other five were unknown to `classify` (`intrinsic:<name>`).

### x86-64, `llc` 19 and 22

- `eh.dwarf.cfa(k)`: `rbp + 16 + sext(k)`. `k` is not `immarg`: a
  variable `k` is sign-extended and added. With `"frame-pointer"="none"`
  the frame pointer is still set up for it.
- `addressofreturnaddress`: `lea [rbp + 8]` (with no frame pointer,
  `rsp` at entry).
- `eh.unwind.init`: the prologue pushes all of `rbx`, `r12`..`r15`, with
  rows.
- `eh.return.i64(off, h)`: `rcx = rbp + 8 + off; mov [rcx], h`; an exit
  that pops every save, then `mov rsp, rcx; ret`. When the function
  writes `rax` or `rdx` they are pushed too, with rows (`rax` at CFA-72,
  `rdx` at CFA-64 beside `unwind.init`): an unwinder installs the
  exception's registers there.
- **Miscompile**: a function with `eh.return` that also returns a value
  on another path sets `eax` and then pops `rax` in the shared epilogue,
  returning the caller's saved `rax` instead (`ret i64 42` returns
  garbage). gcc reloads `rax`/`rdx` only on the `eh.return` exit.
- `sspreq` with `eh.return`: no canary in the function.
- `eh.return.i32` aborts `llc` ("Cannot emit physreg copy instruction").
- `sponentry` aborts `llc` 19 and 22 in instruction selection.
- A variable `frameaddress` depth is a verifier error (`immarg`).

### AArch64, `llc` 19 and 22

- `eh.dwarf.cfa(k)`: `x29 + k`, while the row says the CFA is
  `x29 + 16`. A program comparing `__builtin_dwarf_cfa()` with the
  caller's `sp` before the call gives 0 with gcc and -16 with clang 19,
  clang 22 and clang 22 with SelectionDAG: **miscompiled**.
- `eh.return.i64`: no code at all; the block falls through to whatever
  follows. **Miscompiled.**
- `sponentry`: `x29 + 16`, the CFA (0 from the caller's `sp`).
- `addressofreturnaddress`: `x29 + 8`.
- `eh.unwind.init`: the prologue saves `x19`..`x28` and `d8`..`d15`, with
  rows.
- `returnaddress(1)`: `ldr x8, [x29]; ldr x30, [x8, #8]; hint #7`.

### Decisions

- AArch64 refuses `llvm.eh.dwarf.cfa` and `llvm.eh.return.i64` by their
  rows (`intrinsic:llvm.eh.dwarf.cfa`, `intrinsic:llvm.eh.return.i64`):
  following `llc` would be wrong, and a right answer would have no
  oracle.
- x86-64 refuses `llvm.sponentry` by its row (`llc` cannot build it).
- `llvm.eh.return.i32` stays unknown (`intrinsic:llvm.eh.return.i32`);
  `llvm.localaddress`/`localrecover` are Windows-only and stay unknown.
- x86-64 `eh.return` follows `llc`'s frame and rows, saves `rax` and
  `rdx` always, and reloads them only on its own exit (gcc's choice), so
  the other path returns its value. It is refused under the CET shadow
  stack (`x64:eh-return-shadow-stack`: the `ret` would not match) and in
  `preserve_most`/`preserve_all` functions and coroutine bodies
  (`x64:eh-return-convention`).
- AArch64 `eh.unwind.init` in `preserve_most`/`preserve_all` functions
  and coroutine bodies: `a64:unwind-init-convention`.
