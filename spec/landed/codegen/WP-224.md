# WP-224 — AVX-512 step 5: masked gathers and scatters (x86-64)

Design: `docs/design/0007-avx512.md` (follow-up A of section 5.2, the F
gathers and scatters; the table of section 5.1 has each family's state).
Spec: `spec/codegen.md` §5.6.35 item (10), `spec/mc-x64.md` "EVEX and
the opmask instructions".

## Landed

1. **The encoder** (`crates/hod_mc_x64/src/evex.rs`): the families
   `EGather` (`vpgatherdd`/`dq`/`qd`/`qq`, `vgatherdps`/`dpd`/`qps`/`qpd`,
   `66.0F38 90`..`93`) and `EScatter` (`vpscatterdd`..`vscatterqpd`,
   `A0`..`A3`), W1 for 64-bit elements, and the operand `EVsib` (base,
   vector index, scale, displacement). The constructors `egather`,
   `escatter` and their `try_` twins write the VSIB operand: always a
   `SIB` byte, the index register's bit 3 in `X` and bit 4 in `V'`
   (`zmm16`..`zmm31`), `vvvv` 1111, `disp8*N` with `N` the element's
   bytes, `L'L` the wider operand's length. Preconditions: the opmask is
   never `k0`; a gather's destination is never its index (`#UD` on the
   processor; `llvm-mc` assembles it with a warning). No `{z}` form
   exists. `E3::Pxord` is added to clear a gather's pass-through.
2. **48 intrinsic names** (`hod_ir` `Intrinsic` members, the scale an
   immediate argument, matrix rows `never(X64_ONLY)` / `on(X86_SSE)`, note
   `AVX-512 (WP-224)`): the whole family as LLVM 19 and 22 declare it,
   which holds the census's 16:
   - `avx512.mask.gather.{dpd,dps,qpd,qps,dpq,dpi,qpq,qpi}.512`;
   - `avx512.mask.gather3{div2,div4,div8,siv2,siv4,siv8}.*`, 16 names;
   - `avx512.mask.scatter.{dpd,dps,qpd,qps,dpq,dpi,qpq,qpi}.512`;
   - `avx512.mask.scatter{div,siv}{2,4,8}.*`, 16 names.
3. **The lowering** (`crates/hod_x64/src/x86/avx512/vsib.rs`, reached
   from `avx512.rs` for a name not in its table). The mask (the fewer of
   the data's and the indices' lanes) is moved into `k1` right before
   the instruction, from its register or as a constant through `r11d`:
   the instruction clears its opmask, so each one gets its own copy. The
   indices go to `zmm17`, a gather's pass-through to `zmm16` (cleared by
   `vpxord` when zero or undefined), a scatter's data to `zmm18`; the
   base is the pointer's register, the displacement 0, the scale the
   intrinsic's. A scale that is not a constant 1, 2, 4 or 8, or another
   signature, is `x64:x86-intrinsic-signature`. Feature gates per
   function: `avx512f`; `avx512vl` too below 512 bits; at 512 bits not
   with `evex512` off. Otherwise the intrinsic's own name is refused.
   (`llc` 19 and 22 accept the 128- and 256-bit forms under `avx512f`
   alone, widening them; hod does not.)
4. **The dataflow interpreter** (`crates/hod_x64/tests/x86_avx512.rs`,
   `mod dataflow`) follows memory reached through a vector of indices.
   It reads a VSIB operand, and each gathered lane becomes a node
   `gather` over the base pointer (its displacement folded in), the
   index, the scale, the element and index sizes and, when the lane's
   mask bit is not a constant, the bit and the pass-through. A lane whose
   bit is a constant 0 keeps the pass-through, and the register above
   the lanes is cleared. Each scattered lane is an ordered event, alike.
   The opmask is cleared, and `kxnor k, a, a` sets the bits of its size.

## Refused by name

- Each of the 48 without `avx512f`; the 128- and 256-bit forms without
  `avx512vl`; the 512-bit ones with `-evex512`.
- A scale other than a constant 1, 2, 4 or 8:
  `x64:x86-intrinsic-signature`.

Nothing of the brief is left refused.

## Evidence

**The encoder** (L1 against `llvm-mc` 19 and 22, each the same): group
`evex-vsib` 16,848 encodings equal to `llvm-mc`'s and disassembled as
intended. It has 240 rejections, 48 of them (`k0`) confirmed by
`llvm-mc`; the other 192, a gather's destination equal to its index, are
ones `llvm-mc` assembles with a warning. Constructors: `egather` 8,040
encodings (216 rejections), `escatter` 8,808 (24). Group `evex` is now
36,254 encodings (1,844 rejections) with `vpxord`. The unit tests
`evex::tests::the_measured_examples` and `the_preconditions` pin the
measured bytes, among them `vpgatherdd zmm16 {k7}, [r13+8*zmm31+64]` =
`62 82 7d 47 90 44 fd 10`. The coverage test lists both constructors.

**The lowering, by dataflow** (`vsib_names_agree_with_llc_by_dataflow`):
48 names, 432 functions: a variable mask; constant masks all set, lanes
0 and 2, and none; a zero and an undefined pass-through for the
gathers; scales 1, 2 and 8 beside 4; and the call twice with one mask.
In `llc` 22's code they gather 1,302 lanes and scatter 1,022. hod plain
and hod under every stress option each equal both `llc -O0 -fast-isel=0`
22 and 19 on every function: 0 disagreements in both legs. hod must
equal each `llc` here, not merely one of them.

**Mutations** of `llc` 22's listings, each applied to every gather and
scatter line (`vsib_comparison_catches_mutations`), every one caught:

| mutation | caught |
|---|---|
| another scale | 432 of 432 |
| another index register | 432 of 432 |
| the index and data registers swapped | 432 of 432 |
| another mask register | 480 of 480 |
| mask not copied (the first of two calls on the second's opmask) | 48 of 48 |
| another element size (`d`/`q`, `ps`/`pd`) | 432 of 432 |
| another base register | 432 of 432 |
| another displacement | 432 of 432 |

The mutations skip a mask of constant 0 (the instruction moves nothing),
except "another mask register". The base and the index cannot be
swapped as such: a VSIB base is a general register and the index a
vector one, so the swap does not assemble. "Another base register" and
"another index register" stand for it.

**Refusals** (`vsib_refusals_and_rows`): 48 rows, each accepted with its
features and refused by name as listed above. Each also refuses scales
0, 3 and 16 as `x64:x86-intrinsic-signature`, is supported on x86-64,
and is not built on AArch64.

**Execution.** None: no emulator here runs AVX-512. The test
`vsib_names_agree_with_llc_on_hardware` links 408 functions (the 432 but
the undefined pass-throughs), hod's and `llc` 22's, with a driver. The
driver gives each call a table of 1,024 random bytes, indices in
-32..32 (in bounds at every scale), random data and masks, and a
1,024-byte output table, and compares both tables after the calls. It
runs only with `HOD_X64_AVX512_RUNNER`, on an AVX-512 host:
`HOD_REQUIRE_TOOLS=1 HOD_X64_AVX512_RUNNER=native cargo test -p hod_x64 --test x86_avx512 vsib`.

**Expectations.** `git grep` of each of the 48 names over
`crates/*/tests`, `xtask`, `scripts` and `tests`: at base, no match; at
this branch, only `crates/hod_ir/tests/body_llvm.rs` (its list of
intrinsics) and `crates/hod_x64/tests/x86_avx512.rs` (the new tests).
No expectation named a refusal to update.

**Byte identity**, every 10th entry of each corpus
(`scripts/corpus-bytes.py -j 4` over a manifest of every 10th row),
base `dfa3cd50` against this branch: AArch64 (`.build/corpus`) 669
modules, 669 objects identical, 0 declines, 0 differ; x86-64
(`.build/corpus-x64`) 684 modules, 684 objects identical, 0 declines, 0
differ.

**Tests** at the branch head: `cargo fmt --all --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, and
`cargo test -q -p hod_mc_x64 -p hod_x64 -p hod_ir` (82 test binaries,
693 passed, 0 failed, 4 ignored).
