# WP-214 — moving kiln's pin from `21caaf874` to `21b9110a4`

Landed: kiln 1.1.0 at `21b9110a4` (19 commits after the pin) built
beside the pinned one, both corpora's kiln groups captured again with
it, every changed entry compared with `llc`, the in-repository files
the switch needs regenerated, and what the move is for measured. With
`21b9110a4` kiln classifies x86-64 SysV calls at the translation
unit's AVX ABI level, as clang does (256-bit vectors, and classes and
unions holding exactly one, in `ymm` under `avx`, 512-bit in `zmm`
under `avx512f`); its `opt` route triggers read real attributes (the
`instrument-entry` false positive is gone); `-fstack-clash-protection`
writes `"probe-stack"="inline-asm"` (and `"stack-probe-size"`);
`-grecord-gcc-switches` fills the compile unit's `flags:`;
`-mtls-dialect=gnu2` passes `-enable-tlsdesc` to the back end.
Procedure: `docs/VALIDATION.md` "Moving kiln's pin". Measured with a
release hod of this branch; the reasons pages after merging main at
`9f410277` (wave 16).

## By-value vectors across compilers

`crates/hod/tests/kiln_avx_abi.rs`: a generated grid of 48 callees.
Their types are 256-bit vectors of every element kind, classes holding
one vector (directly, nested, as a one-element array), unions of a
vector and an array, two-member classes (in memory), 128-bit vectors,
integers and floating point. They appear as arguments (up to 14, past
the eight vector registers) and returns; 12 callees are variadic and
read each kind with `va_arg`, and 16 are called through a pointer. The
callee unit and the caller unit are each built by four builders: kiln++
with hod, kiln++ with `llc` 22, clang 19 and clang 22. Every pairing of
a callee builder with a caller builder is linked with bfd, lld and mold
and run under `qemu-x86_64 -cpu max`, for `-mavx`, `-mavx2` and
`-march=haswell`. Every program prints what the all-clang-22 program
prints: for each callee, the hash of the arguments it saw and the hash
of the value its caller got back. That is 144 runs, all the same. The
same callees built by clang 22 without AVX, called by the AVX caller,
print otherwise (the test checks this), so the grid does see the
convention. A class whose base is narrower than itself is left out:
clang 21 and later pass it in memory, clang 19 in `ymm`, and kiln
follows the `-fclang-compat` it is given. 512-bit vectors by value
under `-mavx512f`: kiln writes them as `<8 x double>` arguments and
returns, and hod declines the module by name, `x64:wide-vector-abi`
(WP-208).

## What kiln newly writes or forwards

- **`-fstack-clash-protection`**, with and without
  `-mstack-probe-size=8192`: kiln writes `"probe-stack"="inline-asm"`
  and `"stack-probe-size"="8192"` on its definitions and the
  `probe-stack` / `stack-probe-size` module flags. Through kiln++ with
  `KILN_BACKEND=hod`, strict, on both targets: `backend` is `hod`, the
  objects probe (two probe stores per page loop in a 300000-byte frame
  with an `alloca`; on x86-64 the same `sub`/probe sequence as `llc`'s,
  `0x2000` steps for the 8192 size), and the programs print what the
  `llc` ones print. `crates/hod/tests/kiln_forwarded_options.rs` runs
  this with every linker: 24 runs agree.
  `-fno-stack-clash-protection` after it writes nothing.
- **`-mtls-dialect=gnu2`** (x86-64): kiln passes `-enable-tlsdesc`.
  With the hod of main before wave 16 (`c365f653`), hod refused it by
  name (`hod: error: unknown option '-enable-tlsdesc'`), and kiln
  recorded `backend` `hod-declined`, `hod_reason` `unknown-option`, and
  built the module with `llc` (also under `KILN_HOD_STRICT=1`). With
  main at `9f410277` (WP-213 landed) the same command gives `backend`
  `hod`. A `-fPIC` unit reading an `extern __thread` variable and
  one of its own gets the same relocations as `llc`'s object (2
  `R_X86_64_GOTPC32_TLSDESC` and 2 `R_X86_64_TLSDESC_CALL`), and
  linked into a shared library it prints the same under `qemu-x86_64`.
  `-mtls-dialect=gnu` is built by hod. On AArch64 kiln rejects the
  option, as clang does.
- **`-grecord-gcc-switches`, `-grecord-command-line`**: built by hod
  (`backend` `hod`, `llvm-dwarfdump --verify` clean). `llc` appends
  the compile unit's `flags:` to `DW_AT_producer`; hod writes the
  producer alone. That difference is recorded as an ignored test
  (`recorded_command_line_is_in_the_producer`), with the places to fix
  in `hod_dwarf`.

## The `instrument-entry` false positive

kiln's `KILN_BACKEND=hod KILN_HOD=<this hod> KILN_HOD_STRICT=1` on the
two LLVM 19.1.7 translation units the old trigger kept on the LLVM
route. They were built with their `compile_commands.json` commands
(`.build/oss/llvm-hod`), and only the statistics log's `backend` field
was read:

| unit | old kiln (`21caaf874`) | new kiln |
|---|---|---|
| `llvm/lib/Transforms/Utils/EntryExitInstrumenter.cpp` | `llvm`, triggers `alwaysinline`, `instrument-entry` | `hod`, triggers `alwaysinline`; hod 55 ms |
| `clang/lib/CodeGen/CodeGenFunction.cpp` | `llvm`, triggers `alwaysinline`, `instrument-entry` | `hod`, triggers `alwaysinline`; hod 119 ms (kiln++ 7.2 s, peak 306 MiB) |

Both objects define every symbol of the `llc` build (385 and 4669), and
hod's add some local and weak copies of functions that were inlined
(`.alwaysinline` clones and their callees).
